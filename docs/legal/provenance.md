# Clean-room provenance log

**Project:** FacetForge (iPadOS jewellery CAD) · **Opened:** 2026-11-06 · **Owner:** shahroodazerov-stack

This file records how the specification was produced. It exists so that, at any later point,
the origin of every requirement, constant and asset can be traced to a public source — and so
that no claim of copied code, assets or confidential material can be made against this repo.

## 1. Protocol (binding, see ADR-004)

1. **Specification inputs are public only.** Vendor marketing pages, public documentation,
   published standards (ISO, GIA, Stuller technical guides), public forum threads, public
   tutorial titles/descriptions, Apple developer documentation and public licence texts.
2. **Prohibited inputs.** MatrixGold/Rhino binaries or installers; decompilers; leaked source;
   vendor sample libraries, gem models, head models, textures, icons, help text; NDA material;
   anything obtained by defeating a licence or technical protection measure.
3. **No vendor assets in the product.** Every gemstone, head, shank profile, material preset,
   HDRI, icon, font and screenshot is authored or generated in this repository.
4. **No vendor marks.** "MatrixGold", "Gemvision", "Stuller", "Rhino", "Rhinoceros", "Clayoo"
   and their logos do not appear in the app name, bundle id, icon, screenshots or store listing.
   Research documents may name them factually when citing sources.
5. **Independent implementation.** Implementation agents work from `docs/research/` and
   `docs/MASTER-PLAN.md`, never from vendor artefacts.
6. **Attribution.** Third-party code (openNURBS if vendored, and any Swift package) ships with
   its licence in an in-app NOTICE screen and a repository `NOTICE` file (phase 194).

## 3. Facts that came from standards or vendors (not invented)

- Ring sizing formula and table (US), ISO 8653 reference diameters — dossier C §1.
- Minimum castable dimensions, prong/bezel/channel minimums — dossier C §5–6, from Stuller
  CAD/CAM production standards and independent casting guidelines.
- Metal specific gravities and solid shrinkage ranges — dossier C §7.
- Gem proportion ranges and carat factors — dossier C §3–4, from GIA and trade references.
- openNURBS licence terms — dossier E §6, from the McNeel LICENSE text.
- Apple API behaviour (Pencil, scene resizing, jetsam, simulator Metal limits) — dossier E,
  from Apple developer documentation.

Every one of these is treated as a **design input to be re-verified against the primary source
at the phase that implements it**, not as a guarantee. Where a number is a trade rule of thumb
rather than a standard, the dossier says so and the plan marks it INFERENCE.
